# PLAN-2.md — Orangery Docs, після v0.1.0

Продовження `PLAN.md`. Фази 0–5 і Update 1 закриті функціонально (v0.1.0 pre-release). Відкриті пункти з `PLAN.md` (підпис, нотаризація, ручний QA) переносяться у фазу 6 тут.

Принцип цього етапу: **спочатку довіра, потім фічі, потім амбіції.** Фази 6–7 обов'язкові й ідуть по порядку. Фази 8+ можна перемішувати за фідбеком користувачів.

Статуси: `[ ]` · `[x]` · `[~]` · `[-]` (з причиною).

## Фаза 7 — Довіра до формату (2–3 тижні)

Мета: чужі документи не ламаються. Це важливіше за будь-яку фічу.

### Корпус
- [ ] `tests/fixtures/docx/real/` — 50+ файлів: Word 2016/2021/365 mac і win, Google Docs export, LibreOffice, Pages export, OnlyOffice, старі docx з Word 2007. Джерела: власні документи, які не шкода публікувати, public-domain звіти, gov.ua шаблони, GitHub-репозиторії з тестовими docx (docx4j, python-docx, LibreOffice test corpus — перевірити ліцензії)
- [ ] Окремо приватний корпус поза git (`ORANGERY_PRIVATE_CORPUS` env) — для локального прогону на дипломних і курсових
- [ ] Класифікація фікстур за фічами (numbering, tables, images, fields, sections, tracked) — щоб бачити покриття

### Round-trip
- [ ] Прогін open → save на всьому корпусі: структурний diff XML + render-diff через LibreOffice → PDF
- [ ] Прогін open → мінімальна правка (один символ) → save: перевірити, що змінився лише один run
- [ ] Fuzz: випадкові послідовності команд редактора на кожній фікстурі → save → reopen → save; файл на другому колі має бути ідентичний першому
- [ ] Валідатор OOXML на виході (схема або хоча б Open XML SDK Validator у CI на Windows runner)
- [ ] Читання чужого TOC назад у редаговану ноду — обережно, лише для стандартної структури `w:sdt`/`fldChar` з `w:hyperlink` на bookmark; інакше passthrough як зараз

### Продуктивність
- [ ] Бенчмарк-фікстури: 50, 200, 500 сторінок; таблиця 1000 рядків; 100 зображень
- [ ] Бюджети в CI: відкриття 200 сторінок < 2 с, набір символу < 16 мс p95, збереження < 1 с
- [ ] Профілювання декорацій нумерації/полів — перерахунок інкрементальний, не з нуля
- [ ] Пам'ять: 500 сторінок < 500 МБ

### Нішеві дірки з "чого немає"
- [ ] `wrapNone` / behind text — рендер через абсолютне позиціонування з `z-index` під текстом; редагування позиції — drag
- [ ] `commentsExtended.xml` (w15): відповіді на коментарі, done-позначка, паралельно `commentsIds.xml`
- [ ] `.doc` read-only через конвертацію (варіанти: LibreOffice якщо встановлений, інакше повідомлення "конвертуйте у Word") — `[-]` якщо немає запиту

**DoD:** 50 реальних файлів — 0 регресій round-trip, бюджети продуктивності зелені.

## Фаза 8 — Причина обрати Orangery (3–4 тижні, паралельно з фідбеком)

Мета: фічі, які Word робить погано, а Docs — ніяк. Аудиторія №1 — студенти й викладачі в Україні.

### 8.1 Академічний пакет
- [ ] Шаблон "Курсова/диплом за ДСТУ 3008:2015": Times New Roman 14, інтервал 1,5, поля 20/10/20/20, нумерація заголовків, автозміст, підписи рисунків/таблиць за ДСТУ, нумерація сторінок без першої
- [ ] **Перевірка за ДСТУ** — панель: сканує документ і показує порушення (шрифт, інтервал, поля, заголовки не в стилі, рисунок без підпису, пропуск у нумерації, посилання на неіснуючий рисунок). Кожне — з кнопкою "виправити"
- [ ] Список джерел за ДСТУ 8302:2015: діалог введення джерела за типом (книга, стаття, сайт) → правильний рядок; посилання в тексті `[3, с. 12]` полем `REF` на пункт списку
- [ ] Перехресні посилання (`w:REF`, `w:PAGEREF`) на рисунки, таблиці, розділи — діалог вставки з пошуком
- [ ] Bookmarks: панель, створення, перехід

### 8.2 Формули
- [ ] OMML (`m:oMath`) читання і запис — рідний формат Word для формул
- [ ] Редактор формул: LaTeX-подібний ввід із live-превью (MathLive або власний на KaTeX), конвертація LaTeX ⇄ OMML
- [ ] Нумерація формул `(2.3)` праворуч через табуляцію — як за ДСТУ
- [ ] Round-trip тести: формули з Word відкриваються й зберігаються без змін

### 8.3 Мова
- [ ] Перевірка орфографії: Hunspell через Rust (`hunspell-rs` або власний біндинг), словники uk/en/pl/de, підкреслення, контекстне меню, власний словник користувача
- [ ] Визначення мови run-а з `w:lang`, автоматично для змішаних текстів
- [ ] Переноси (`w:hyphenation` + власна розстановка через hyphen-словники) — опційно
- [ ] Розширена автозаміна: користувацькі правила, `--`, `(c)`, дроби

### 8.4 Повсякденне
- [ ] Галерея шаблонів: лист, резюме, звіт, заява, ДСТУ-курсова — з превью
- [ ] Порівняння документів (diff двох docx → track changes) — вбивча фіча, Word робить погано
- [ ] Історія версій документа: локальні снапшоти при кожному збереженні, перегляд, відкат, diff між версіями
- [ ] Експорт PDF/A для подачі в архіви/деканат
- [ ] Вставка з Docs/Word через буфер — перевірити, що стилі та списки не розповзаються
- [ ] Watermark, фон сторінки, рамки сторінки (є в `sectPr`)
- [ ] Mail merge — `[-]` до запиту

**DoD:** твоя власна дипломна пишеться в Orangery від початку до захисту без відкриття Word.

## Фаза 9 — Справжня пагінація (R&D, 4–8 тижнів, окрема гілка)

Мета: закрити головний розрив із Word. Не починати до завершення фази 7.

- [ ] ADR: підхід. Кандидати:
  1. **Layout pass поверх ProseMirror** — після кожної транзакції асинхронно міряємо висоти блоків, обчислюємо розриви сторінок, малюємо декораціями (page gap + spacer). Текст лишається одним contenteditable. Найреалістичніше.
  2. Окремий рендер-движок (canvas/власний layout) — повний контроль, але це "переписати редактор". `[-]`.
- [ ] Прототип на гілці: 50-сторінковий документ, розриви сторінок обчислюються < 50 мс після правки, без стрибків курсора
- [ ] Widow/orphan control, `keepNext`, `keepLines`, `pageBreakBefore` — усе з `w:pPr`, тобто вже в моделі
- [ ] Розбиття таблиці між сторінками з повторенням заголовка (`tblHeader`), заборона розриву рядка (`cantSplit`)
- [ ] Колонтитули на кожній сторінці, парні/непарні (`evenAndOddHeaders`), перша сторінка розділу
- [ ] Виноски внизу саме тієї сторінки, де посилання
- [ ] Номери сторінок у полях `PAGE`/`NUMPAGES`/`PAGEREF` рахуються з layout, не approx
- [ ] Друк/PDF з нашого layout, а не з webview-верстки — щоб те, що бачиш, збігалося з тим, що друкуєш
- [ ] Порівняння з Word на корпусі: кількість сторінок і місця розривів на 30 документах — ціль ≥ 90 % збігу
- [ ] Перемикач "Сторінковий / Неперервний" вигляд — неперервний лишається fallback

**DoD:** 30 документів корпусу — кількість сторінок як у Word ±1, друк збігається з екраном.
